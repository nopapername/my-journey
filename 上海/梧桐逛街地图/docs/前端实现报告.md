# 前端实现报告

执行范围：实施计划 Task 2。依据已批准设计与主代理的数据接口完成静态前端，未修改研究或数据文件。

## 已实现

- `dist/index.html`、`style.css`、`app.js`：奶白与深绿视觉；桌面左侧清单、右侧地图；手机横向路线选择、地图、清单顺序。
- 默认 `r1` 和核心店铺，支持全部路线、店名／风格／地址／标签搜索、核心店铺开关及正常收录／待核实／过期／全部状态筛选。默认仅显示 `active`，并明确其不代表当前营业。搜索临时覆盖全部路线、资料状态与非核心记录，清空恢复原筛选。
- 稳定的店铺编号用于清单和地图；地图弹窗展示风格、地址、来源及位置提示。高德始终按“上海＋店名”搜索，不把近似坐标作为导航终点。
- `exact` 绘制实心编号点；`approximate` 绘制空心虚线编号点，卡片和弹窗明确标注街段参考；`unknown`、无效或非数值坐标不绘制。
- 路线 `path` 使用虚线表达核心步行参考线，页面说明基于参考点规划，非现场核验导航。步行距离与分钟依据数据中的 OSM 规划估算，不包括逛店、等候或远端加选，折叠区可打开路线依据链接。
- 来源折叠面板展示每篇链接、阅读范围和资料缺口。输出文本使用 `textContent`，外链限制为 HTTP(S)。
- 复用本地 Leaflet 资源及许可证，底图使用 OpenStreetMap。Leaflet 未载入或初始化失败保留清单；瓦片失败提示后仍保留标记和清单。主代理发现 CARTO 返回需 API Key 的图片，已改用 OSM 标准瓦片。
- 手机点清单卡片后滚动至地图；点击地图标记仅高亮卡片，避免页面跳离地图。

## 接口与裁定

- 数据读取 `window.DATA`，字段沿用主代理约定；数据文件缺失时显示资料未载入提示。
- `mapEligibility(shop)` 返回 `exact`、`approximate` 或 `null`，不把字符串坐标自动转换为数字。
- 编号由路线顺序及 `shopIds` 顺序生成，每路线远端加选置底，随后补充未列入路线的条目；搜索与状态切换时保持不变。清单遵循相同顺序。
- 恢复全图只恢复地图视野，不改变当前路线和筛选；“全部路线”按钮负责更改路线筛选。

## 第二轮小修

- `shop.note`、`coordinateNote` 及 `evidenceUrl`／`anchorEvidenceUrl`／`geocodeEvidenceUrl` 收进卡片“位置与资料说明”折叠区，风格、地址、标签、来源与高德保持可见。可见 warning 缩为简短提示。
- 首页动态显示全数据记录数与有地图参考点的条数，并可见展示 `data.coverageNote`，不把记录覆盖等同于已全部核实。
- `shop.extension` 标记“远端加选”，路线说明与弹窗明确核心时长不包含全部加选。
- 同坐标记录合并为“首个编号 + 额外记录数”标记，popup 逐店按钮可访问所有资料，点击卡片直接打开对应店的弹窗。混合精确与近似组按近似展示。
- 同点位不等同于确证同楼／同址，弹窗明确共用参考点为示意，并要求核对各店门牌。选中店弹窗可直接访问原始地址、定位参照及地理编码证据。

## 最终前端调整

- 默认勾选核心，清单提示取消可查看完整记录。
- 搜索自动覆盖全路线、全状态与非核心条目，显示明确搜索范围；搜索期间状态与核心开关暂停，清空关键词恢复原筛选。选择路线会结束搜索。
